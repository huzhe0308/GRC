# BS EN 15722:2020 — eCall (112) Emergency Call System

## Overview

BS EN 15722:2020 is the UK implementation of EN 15722:2020, a European Standard defining the Minimum Set of Data (MSD) for the pan-European eCall emergency call system. Approved by CEN on 5 July 2020 and published by BSI on 30 September 2020, it supersedes BS EN 15722:2015. The standard specifies the data concepts, representation, and ASN.1 encoding for the MSD transmitted from in-vehicle eCall systems to Public Safety Answering Points (PSAPs) in the event of a crash or emergency. It is estimated that fully deployed eCall could save up to 2,500 fatalities annually in the EU and reduce injury severity.

## Scope and Requirements

- **Scope (Clause 1):** Specifies the standard data concepts comprising the "Minimum Set of Data" (MSD) to be transferred from a vehicle to a PSAP in the event of a crash or emergency via an eCall communication transaction. Does not specify communications media, protocols, or transmission methods.
- **MSD Data Concepts (5.1.1):** The MSD is a direct, timely message to the PSAP operator; information elements were selected based on relevance in emergency rescue situations. Includes an "optional additional data" block for situation-specific information.
- **MSD Representation (5.1.2):** The message shall be sent in the sequence defined in the ASN.1 definition (Annex A). The MSD for Pan-European eCall shall be represented in ASN.1 using **Unaligned Packed Encoding Rules (UPER)** per ISO/IEC 8825-2.
- **MSD Versioning (5.1.3):** Later versions shall be backwards compatible. The main structure contains two elements: the `msdVersion` (designating encoding rules) and the MSD data itself. Version 3 is the current basic version; version 1 was withdrawn due to erroneous ASN.1 representation; version 2 (2015) shall no longer be implemented in IVS devices but must be supported by PSAPs.
- **MSD Distribution (5.1.4):** The encoded MSD length (including optional additional data) **shall not exceed 140 bytes**. Additional data concepts may not exceed **94 bytes** of UPER-encoded data. Payload bytes outside the ASN.1 message length shall be ignored by the receiving entity.
- **Additional Data (5.1.5):** Optional additional data consists of a relative OID plus data content. OIDs are allocated by CEN/TC 278/WG15. Personal data shall not be included unless explicitly authorized per EU 2016/679 (GDPR).
- **ISO Object Identifier (5.2):** eCall has been allocated OID **1.0.14817.106.2.1**. Three sub-nodes: `.1` for Mandatory Data Concepts, `.2` for Optional Data Concepts, `.3` for eCall data elements. The OID is not transmitted over the air between IVS and PSAP.
- **MSD Contents (5.3.2, Table 1):** Mandatory fields include: `msdVersion` (INTEGER 1..255), `messageIdentifier` (1..255, incremented per retransmission), `automaticActivation` (true/false), `positionCanBeTrusted` (false = <95% confidence within ±150 m), `vehicleType` (UNECE categories M1–M3, N1–N3, L1–L7, O, T, R, S, G, Other), `VIN` (per ISO 3779), `vehiclePropulsionStorageType` (gasoline/diesel/CNG/LPG/electric/hydrogen/other), `timeStamp` (seconds since 1970-01-01 UTC, failure = 0), `vehicleLocation` (WGS84 lat/lon in milliarcsec), `vehicleDirection` (2° steps, 0–358°), `recentVehicleLocationN1` and `recentVehicleLocationN2` (deltas within 15-second window). Optional: `numberOfOccupants` (0..255, 255 = unknown) and `optionalAdditionalData`.
- **Coordinate Ranges:** Latitude: ±324,000,000 milliarcsec (±90°); Longitude: ±648,000,000 milliarcsec (±180°). Invalid/unknown latitude = value 2,147,483,647. Both lat and lon = 0 → location invalid/unknown.
- **Recent Location Deltas:** `latitudeDelta`/`longitudeDelta` range −512..511 in units of 100 milliarcsec (≈3 m on Earth); max ±1,580 m.
- **Normative References (Clause 2):** EN 16062 (HLAP for GSM/UMTS), EN 16102 (third-party support requirements), ISO/IEC 8825-2 (PER specification).
- **Annex A (normative):** ASN.1 definition of the MSD, including syntax check and encoded MSD examples.
- **Annex B (informative):** ASN.1 data representation explained — BER, DER, PER/UPER, XER, EXER encoding rules with examples.
- **Annex C (informative):** Formal XML Schema Definition (XSD) for MSD, used in TPSP-to-PSAP applications.
- **Annexes D–E (informative):** Rationale for MSD data concept elements; Object Identifiers and ISO standards relationship.

## Key Changes from EN 15722:2015

- Correction of typing errors and added clarifications for frequently asked questions
- Inclusion of recent vehicle locations (N1, N2) as **mandatory** fields (were optional in v2)
- MSD field "numberOfPassengers" replaced by "numberOfOccupants"
- Expanded vehicle category enumeration to cover full UNECE categorization
- Updated privacy requirements to include EU 2016/679 (GDPR)
