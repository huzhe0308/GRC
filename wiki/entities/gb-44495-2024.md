# GB 44495-2024 汽车整车信息安全技术要求

## Overview

GB 44495-2024 is a Chinese mandatory national standard specifying cybersecurity technical requirements for vehicles. Published on 23 August 2024 with effective date 1 January 2026, it was technically developed with reference to UN Regulation No. 155 (UN R155). The standard covers vehicle cybersecurity management system requirements (Clause 5), information security basic requirements (Clause 6), information security technical requirements including external connection security, communication security, and software upgrade security (Clause 7), type approval procedures (Clause 8), same-type judgment (Clause 9), and implementation schedule (Clause 10). The accompanying operation regulation (EX_30) provides 38+ detailed check points for management system and 35+ check points for technical requirements, referencing UN R155 interpretation documents. ^[raw/papers/CS_1_1_GB_44495-2024.md] ^[raw/transcripts/EX_30_GB44495_Operation_Regulation.md]

## Scope and Requirements

- **Clause 5 (CSMS Management System)**: Manufacturer must establish vehicle lifecycle CSMS covering development, production, and post-production phases; includes risk identification/assessment/classification/treatment, testing process, attack/threat/vulnerability monitoring and response, and supplier management
- **Clause 6 (Basic Requirements)**: Product development follows CSMS; risk identification and management; key element identification and risk assessment; risk treatment per Clause 7; testing verification; attack monitoring/detection/forensics capability; cryptographic algorithms must be public/published/valid; cryptographic module requirements; default security settings; data processing per GB/T 44464-2024
- **Clause 7.1 (External Connection Security)**:
  - **7.1.1.1**: No unresolved high+ vulnerabilities published ≥6 months prior by authoritative platforms (e.g., NVDB-CAVD); "treatment" includes elimination or mitigation measures
  - **7.1.1.2**: Vehicle must close non-essential network ports
  - **7.1.2 (Remote Control)**: Authenticity/integrity verification of remote control commands; access control disabling unauthorized commands; security logs (time, sender, target, result) retained ≥6 months; integrity verification of remote control systems
  - **7.1.3 (Third-party Apps)**: Authenticity/integrity verification of authorized third-party apps; installation prompt and access control for non-authorized third-party apps
  - **7.1.4 (External Interfaces)**: Access control for USB, diagnostic, and other physical interfaces; USB/SD file format restrictions and signed application requirements; virus risk handling for USB devices
- **Clause 7.2 (Communication Security)**: Cloud platform identity verification; V2X certificate validation; wireless communication integrity; external data instruction access control; key instruction uniqueness; sensitive data confidentiality; physical attack defense; internal network segmentation; DoS attack detection; malicious V2X/diagnostic data detection; security event logging ≥6 months
- **Clause 7.3 (Software Upgrade Security)**: OTA and offline upgrade security requirements
- **Clause 8 (Inspection and Test Methods)**: Procedures for type approval testing
- **Clause 9 (Same-Type Judgment)**: Criteria for 同一型式判定 (same-type judgment) for vehicle type approval
- **Clause 10 (Implementation)**: Defines implementation timeline and transitional provisions
- **Operation Regulation (EX_30)**: Provides 38+ check points for management system and 35+ check points for technical requirements, with detailed evidence requirements referencing UN R155 interpretation documents

## Technical Details

- Vulnerability disclosure threshold: High+ vulnerabilities from authoritative platforms (e.g., **NVDB-CAVD**) must be resolved within **6 months** of publication (Clause 7.1.1.1)
- Security log retention: **≥6 months** for remote control commands and security events (Clauses 7.1.2.3, 7.2)
- External interfaces requiring protection: USB, SD card, diagnostic (OBD), and other physical interfaces
- Sensitive personal information defined: location, audio, video, images, biometrics
- Cryptographic algorithm requirements: must be publicly published and valid
- Effective date: **1 January 2026**
- Applicability threshold: vehicles with ≥1 ECU in categories M, N, O
