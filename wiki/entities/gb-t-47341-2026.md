# GB/T 47341-2026 智能网联汽车 车载操作系统技术要求及试验方法

## Overview

GB/T 47341-2026 specifies technical requirements and test methods for vehicle-info operating systems (车载操作系统) in intelligent and connected vehicles. Published on 31 March 2026 with effective date 1 July 2026, the standard covers the software platform that manages and controls in-vehicle software and hardware resources to provide services beyond driving automation functionality. It addresses system architecture (single and multi-system), resource abstraction, application frameworks, thing models, and account management systems. The standard defines abbreviations including API, ASIL, CA (Client Application), CAN, DMS, ETC, GNSS, IC, MCU, OBD, and references key cybersecurity and data security standards.

## Scope and Requirements

- **Scope**: Specifies technical requirements for vehicle-info operating systems and describes corresponding test methods
- **Applicability**: Applies to M and N category vehicles equipped with vehicle-info operating systems; other vehicle types may refer to this standard
- **System Definition**: Vehicle-info OS runs on in-vehicle infotainment and instrument hardware, managing software/hardware resources to provide services beyond driving automation
- **Architecture Types**:
  - **Single-system architecture (单系统架构)**: Single OS running on one hardware platform
  - **Multi-system architecture (多系统架构)**: Multiple OS on shared hardware using hardware isolation, hypervisor (虚拟机管理器), container (容器), or combinations thereof
- **Key Components**:
  - **Resource abstraction (资源抽象)**: Runs above OS kernel, providing hardware resource physical characteristics and interfaces for applications and base services
  - **Thing model (物模型)**: Digital description of objects, including three-layer structure: elements (元素), components (组件), and thing templates (物模板)
  - **OEM accounts**: Owner (所有者), non-owner (非所有者), guest (访客) with account binding and multi-account management
  - **System accounts** and **cloud application accounts**
- **Abbreviations**: API, ASIL, CA (Client Application), CAN, DMS, ETC, GNSS, IC, MCU, OBD
- **Normative References**: GB/T 41388-2022 (trusted execution environment), GB/T 44464-2024 (vehicle data general requirements), GB 44495-2024 (vehicle cybersecurity), GB 44496-2024 (software update requirements)

## Technical Details

- Published: 2026-03-31; Effective: 2026-07-01
- Multi-system isolation technologies: hardware isolation, hypervisor, container, or combinations
- Thing model structure: elements → components → thing templates (3 layers)
- OEM account hierarchy: owner > non-owner > guest
- References GB/T 41388-2022 (TEE) for trusted execution environment
- References GB 44495-2024 and GB 44496-2024 for cybersecurity and OTA requirements
- References GB/T 44464-2024 for data security compliance
- Includes ASIL (Automotive Safety Integrity Level) in abbreviations, indicating functional safety considerations in OS design
